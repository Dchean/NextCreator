## F-R4-1（本次判 FAIL 的真实新缺陷）：flowStore 撤销快照复活陈旧的 queued:true，造成可跨重启的 REQ-001 类永久锁
触发序列（全部为真实入口）：队列暂停（或并发占满）→ 点击生成 → 节点显示「排队中」、写入 queued:true → 用户在等待窗口内做**任意可撤销的画布编辑**（addNode/removeNode/connect/align/duplicate 都会调用 saveToHistory，而 saveToHistory 存的是 flowStore.nodes 的**完整快照**，含 queued:true；窗口 = 整个排队等待期，暂停时无上限）→ 用户取消该排队任务（标记被正确清为 false）→ 用户按 **Ctrl+Z**（FlowCanvas.tsx:184 与工具栏按钮均绑定）→ 快照把 queued:true 写回 flowStore。此时活动任务数 == 0，且**没有任何路径会再清除它**：pump.finally 不会再触发，重启恢复只处理 status==='queued'（该任务已是 cancelled），cancel/reject 复核都需要存在活动任务或新的入队。随后 App.tsx:170 的 800ms 防抖把 true 落盘进画布副本，重启后由 App.tsx:154 setNodes 载回 → 节点永久显示「排队中」、ImageGeneratorNode.tsx:215 canRun=false、按钮永久禁用。唯一出路是对 error/cancelled 任务点「重试」（QueuePanel.tsx:196-222）——那会发起真实计费 API 调用。

总控独立验证（读源码确认机制，并用审查者探针复现关键链条）：
- flowStore.ts:78-102 createLightweightSnapshot：非「重数据」节点**原样返回**（:84），随后 structuredClone(lightNodes)（:99）—— 因此 queued:true 确实进入历史快照。
- flowStore.ts:736-757 undo：:749-752 `set({ nodes: previousState.nodes, ... })` —— **整体恢复**快照节点，含 queued:true。
- 运行审查者探针 probe-r4-undo-cancel.mjs 与 probe-r4-undo-restart.mjs，崩溃前打印的决定性链条完全一致：① 暂停下点击生成 → 标记=true、队列=queued；② 等待期新增节点 → history=1、**快照含 queued:true=true**；③ 取消后 → 标记=false；④ Ctrl+Z → **标记=true、活动=0**；⑤ 防抖回写画布副本后 → **canvasStore.queued=true**（这份会落盘并被 setNodes 载回）。
