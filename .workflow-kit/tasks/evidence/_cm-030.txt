chore(release): 版本对齐到 0.3.0，并加发布守卫与残留资产清理

问题：安装包文件名取自 tauri.conf.json 的 version，Release 名称取自 git tag。
此前 tag 已到 v0.2.10/v0.3.0，而应用版本停在 0.2.6→0.2.10，导致发布页标题与
安装包文件名不一致（标题 v0.3.0、包却是 NextCreator_0.2.10_*.exe）。

本次改动：
1. 版本升到 0.3.0，四处同步：package.json、tauri.conf.json、Cargo.toml、Cargo.lock；
2. 新增 .github/scripts/verify-version-alignment.mjs —— 发布前强制校验
   tag == package.json == tauri.conf.json == Cargo.toml == Cargo.lock，不一致直接失败，
   从流程上杜绝再次错位；
3. 新增 .github/scripts/prune-release-assets.mjs —— 同一 tag 重发时清掉不属于当前
   版本号的旧资产，避免发布页同时挂两个版本的安装包；
4. release.yml 接入上述两步；Rust 缓存 shared-key 随版本更新。

验证：本地 cargo build --release 产物版本戳 0.3.0；tsc exit 0；
queue-regression 9/9 PASS；守卫脚本对 v0.3.0 通过、对 v9.9.9 正确失败。
