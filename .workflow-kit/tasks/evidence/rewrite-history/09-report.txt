## 授权与安全边界

- 密钥值全程未打印、未写入任何文件；扫描时只输出计数、路径与提交哈希。

## 操作步骤（脚本在 .workflow-kit/tasks/evidence/rewrite-history/）
1. 01-inventory：盘点密钥在历史中的分布 —— 仅 3 个提交（b59f07e / 98dc29d / af832d1）、2 个路径；
   工作流状态文件无对旧提交哈希的引用（改写后无需修补）。
2. 02-backup：仓库外完整备份（C:\Users\A\NextCreator-key-backups\pre-rewrite\）：
   mirror clone + git bundle + 清单；已用 bundle 试克隆验证可恢复。
3. 03-rewrite：git filter-branch --index-filter（git rm --cached --ignore-unmatch 两路径，
   --prune-empty，--tag-name-filter cat）。首次运行被自检防护拦下（工作树不干净），
   先提交前置脚本后再执行。改写后 tag 全部指向新哈希，但本地分支 main 未被更新（见 06）。
4. 06-finalize：把 refs/heads/main 指到改写后的 v0.2.10 tip；删除 filter-branch 的
   refs/original/* 备份引用与过期的 refs/remotes/NextCreator/*；reflog 过期 + gc --prune=now。
5. 07b-push：GitHub 拒绝删除默认分支，故直接 force-push main（af832d1 → 85cfd8f），
   15 个 tag 先删后推（远端 tag 计数 22 = 15 个版本 tag + main 同名 tag + 其它既有 tag）。
6. 08b-verify-remote：从 GitHub 重新克隆，`git grep --fixed-strings` 逐提交扫描全部
   117 个提交 —— 0 命中；两个路径在全历史 0 次出现。
